## Phase Goal

**As a** musician (or the AI agent I tell to run tests), **I want to** measure my audio round trip from the `soundping` CLI, **so that** I get a trustworthy, saved number on the engine every later recipe reuses.

<objective>
Stop broken setups before they produce numbers: missing mic permission (naming the app that owns it), a muted output, silent or clipping input, and nothing heard even at the safe ceiling each become a named preflight cause (ENG-03). Level is found by a gentle ramp and locked for the run (D-14). Add the one-shot `--in-channel auto` helper (D-11).

Purpose: on macOS a denied microphone is silence, not an error (STACK); an agent-launched CLI inherits the terminal's permission (RESEARCH P4). Hearing safety: never start loud.
Decision under Claude's discretion (RESEARCH open question 1, D-14 is listed under Claude's Discretion): probes are a separate, uncounted `probe` phase, and the 5 declared warm-ups run after the lock at the locked level. This keeps D-14's intent (probe hits are thrown away like warm-ups) while the ramp may need up to 7 steps, more than 5 warm-ups (RESEARCH P5). Flo can veto this at plan review.
Output: ResponsibleApp, Preflight, LevelRamp, ChannelProbe, probe/levelLocked events, `--max-level`, `--listener`, simulation knobs for permission/zeros/mute/loop channel.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| macOS TCC → SoundPing | microphone consent owned by the responsible app, not by SoundPing |
| SoundPing output → speakers/headphones → ears | test sounds reach a person's hearing |
| process environment → app naming | `__CFBundleIdentifier` / TERM_PROGRAM can be set by anyone |

| T-01-28 | Safety (hearing damage) | LevelRamp | high | mitigate | first probe −48 dBFS, +6 dB steps, per-listener ceilings (headphones −30), `--max-level` only by explicit flag; LevelRampTests pin all of it |
