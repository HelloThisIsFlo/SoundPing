## Phase Goal

**As a** musician (or the AI agent I tell to run tests), **I want to** measure my audio round trip from the `soundping` CLI, **so that** I get a trustworthy, saved number on the engine every later recipe reuses.

<objective>
Turn the simulated round trip into the trustworthy number: prove the host clock agrees with the sample clock (CAL-03, the exit gate MIDI work depends on), report the measured figures next to what macOS claims (RES-02), measure two-device setups through the host path, and store each run as a round-trip calibration (CAL-02).

Purpose: Phase 2 aligns MIDI to audio through host time, so the host path must be proven first; a number that hides an offset is worse than none (PROJECT accuracy constraint). Everything here is proven in simulation; plan 01-07 runs it on hardware and plan 01-09 gates it on the bench.
Output: Clock timelines + self-test, `selftest clock`, clock-selftest.json, measured path/appRoundTrip/ioOffset/host path, reported-vs-measured output, calibrations.json.
</objective>
