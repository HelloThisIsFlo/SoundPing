## Phase Goal

**As a** musician (or the AI agent I tell to run tests), **I want to** measure my audio round trip from the `soundping` CLI, **so that** I get a trustworthy, saved number on the engine every later recipe reuses.

<objective>
Make every run watchable live and machine-readable: `--ndjson` streams the RunEvents, the default pretty mode shows each hit as it lands plus a speed-test-style summary, and every failure comes out as a named code with its own exit code (D-01, D-03).

Purpose: Flo mostly drives tests through an agent (D-01), so the agent must branch on codes, never on prose; Flo still needs to watch hits land when he runs it himself (ENG-02).
Output: NDJSON + pretty renderers, error envelope + exit codes, a CLI test target, engine stream tests, extended ci-sim.sh.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-11 | Tampering | stdout in JSON modes | medium | mitigate | data-only stdout, progress to stderr; ci-sim.sh parses every ndjson line and the single --json object |
| T-01-12 | Information disclosure | error envelope context | low | accept | context holds device names, the store path and the terminal app name only; local tool, no secrets exist in Phase 1 |
| T-01-13 | Repudiation | agent misreading failures as success | medium | mitigate | distinct non-zero exit code per class; gate failures exit 3 even though the result is saved |
